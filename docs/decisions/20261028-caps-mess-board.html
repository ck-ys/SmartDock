能力页「还是有点乱」：四条病根 + 五道选择题

AI 助手管理 → 能力 · 2026-10-28 · 这一板只出方案，没回执不动代码

上一批把能力清单本身理顺了（一行一件事、去掉重复状态），但整页看上去仍然乱——乱的地方不在那张清单， 而在它周围：一个页签里塞了三件不同性质的事，三段各用一套版面语言，行与行之间的横向关系也没说清。 下面先摆实测证据，再给五道题，每题 2-3 案、标★推荐，能改的都给前后模拟。

实测：能力页 1745px，装了三段 8 种字号 / 10 种圆角 / 124 条分隔线 行内 800px 空档 上一批的 51 条断言仍全绿

四条病根（都是量的，不是感觉）

#病根实测证据为什么看着乱
1 一个页签装了三件事 能力页 = 能力清单 917px + 外部服务 266px + 助手行为总纲 518px，共 1745px。这三件事分别是「权限配置 / 服务登记 / 提示词文档」。 三段的工作性质不同，读者被迫在同一个页签里切换三种心智。
2 三段各用一套容器 能力清单：无卡平铺，只有分隔线；外部服务：卡里再套一张带表头的表；行为总纲：卡片里再套灰描述条 + 灰代码块（三层）。 三种「深度」并排，眼睛找不到统一的边界规则。
3 行的左右两半没关系 行网格实测 806px 56px 212px 44px：名字列吃掉 806px，名字写完到徽章之间空着约 800px；每组的「当前生效 → 本租户覆盖」还重复了 3 次，却没有列头把两半连起来。 空档没有语义，读者不知道该横向对齐什么。
4 顶部叠了四条横带 标题行（含「只看高危」）→ 说明段两行 → 黄条 42px → 分段控件行，四条之后才见到第一行内容；全页 8 种字号（10/11/11.5/12/12.5/13/14/15）、10 种圆角、9 种文字色、124 条分隔线。 进门先过四道不同高度的横带，节奏被打碎。

顺带发现一条旁证：总览页「这一页管什么」的三条简介里，能力写的是「助手会什么、谁能用、哪项危险」，规则写的是「租户开关、模型与费用、额度」—— 没有一条提到「行为总纲」。它现在挂在能力页，但连页面自己的导览都没给它位置。

这批活怎么干

先定架构 → 再统容器 → 再治行与顶 → 最后小修
  1. 第 1 步 先答 Q1（架构）。因为它决定后面几步改哪个文件、改哪一段；答完只搬迁不改样式，搬完先截一张「结构图」确认三段位置对了。
  2. 第 2 步 答 Q2（容器）+ Q4（顶部）。这两条都在同一页的样式层，一起做一次回归：1440 / 390 两档、亮暗两主题、零横向溢出。
  3. 第 3 步 答 Q3（行的横向关系）。动的是行网格与列头，必须逐行量列宽，并用「十个下拉零截字」这条老断言复验（历史坑：加宽后仍差 2px）。
  4. 第 4 步 答 Q5（外部服务单元格小修）+ 收字号圆角。这一层只做减法，不做新交互。
  5. 第 5 步 收口。真机断言（沿用 probe-prime-live.mjs，新增列头 / 容器 / 横带三条）→ 前后对比页（双写）→ 更新日志一条 → 人话日志 → 提交。

每步验收口径固定：DOM 实算（不是看截图猜）+ 截图目检 + 390 零溢出 + 下拉零截字 + 暗色。任一步不过就停在那一步，不往下叠。

Q1 · 行为总纲放哪

这一题定架构，后面几步都跟着它走

现状：能力页装「能力清单 / 外部服务 / 助手行为总纲」；规则页装「租户设置 / 模型与费用 / 每人每天额度」。 行为总纲是助手每次回答前都读的「岗位说明」文档（7 段，可逐段改），本质是「它被要求怎么做事」。

★ 推荐 甲 · 搬到「规则」页，放在规则页第一段

能力页只留「能力清单 + 外部服务」两段。规则页变成「行为总纲 → 租户设置 → 模型与费用 → 额度」，读起来是「它被要求做什么 → 怎么收费 → 能用多少」，一条线。

好在：总分关系立住，能力页从 1745px 降到约 1200px；总览导览文案补一句就能自洽。
代价：规则页变长（1978 → 约 2500px），需要在规则页顶部加一排「跳到哪一段」的小目录。
乙 乙 · 独立成第 5 个页签「提示词」

顶部导航变「总览 / 能力 / 规则 / 运营 / 提示词」，文档拿到整屏空间。

好在：编辑体验最好，不受别的段落挤压。
代价：上一批刚从 8 个页签收到 4 个，现在又加回 5 个；手机档页签本来就要横滑，再挤一格。
丙 丙 · 留在能力页，收进折叠组

能力页变成「能力清单 + 外部服务 + 一个默认收起的『助手行为总纲（7 段）』」。

好在：零搬迁，路由和书签都不变，改动最小。
代价：根因没除——一个 518px 的编辑器藏在「能力」里；展开后照样是三种版面语言并排。
方案第一次来日常用防呆适合谁代价
甲 ★能力页只有两段，一眼看到底改提示词去规则页第一段，顺手看额度规则页顶部有段目录，不会找不到想「一眼看懂这页管什么」的单位搬迁 + 规则页加小目录

丙仍要看到三个不同版面多点一次展开折叠组标题写清段数，不会漏只想尽快收口、不改结构乱在根上，后面还会被提一次

Q2 · 三段用同一套容器

现在三段三种「深度」

医生的直觉：同一页里的边界规则只能有一套。要么都用卡、要么都不用；混着用，眼睛会一直找「为什么这段有框那段没框」。

★ 推荐 甲 · 每段一张卡，卡内只用分隔线

三段都是「同规格白卡（同内边距、同 8px 圆角、段间同 20px 间距）」；卡里的表格和清单只留分隔线，不再套第二层边框。

好在：产品基线本来就是卡片语言（壳层、系统管理都一样），把「三套深度」压成「一套深度」，一眼就是三段。
代价：能力清单从「通栏平铺」变成「卡内清单」，左右各让出 14-16px，行宽短一点点（下拉不会受影响）。
乙 乙 · 全部去卡，只留分隔线与段标题

三段都像现在的能力清单：无卡、通栏、靠分隔线与段标题分层。

好在：最安静、最省像素，长列表天然适合这种。
代价：行为总纲的文档编辑器会「飘」——灰色描述条与代码块失去外框后没有边界，改提示词时容易点错区域。
丙 丙 · 保持现状，只对齐内边距与表头

清单继续平铺、后两段继续卡片，只把内边距、表头字号、段间距调成一致。

好在：改动最小，风险最低。
代价：「有没有卡」仍然在表达分区，一眼看去还是两种语言，大概率这次还是觉得乱。
方案第一次来日常用防呆适合谁代价
甲 ★三段三段卡，边界规则统一行宽略窄，操作位置不变卡内不再套框，视觉噪声少一层希望「和企业级后台一致」的单位清单左右各让 14-16px
乙最干净，像素利用率最高文档区没有边框，长文容易看串代码块边界消失只看列表、不改提示词的人文档编辑器体验下降
丙仍有两种分区语言不变不变不打算再改的人这次的意见大概率还会再提一遍

Q3 · 行中间那 800px 空档

不是要填满它，是要说清它是什么

现在：名字写在最左，控制在最右，中间约 800px 没有任何东西；每组头上还有一句「当前生效 → 本租户覆盖」重复 3 次。 读者要横向跳 800px 才能把「联网搜索」和它的「高危」连起来。

★ 推荐 甲 · 加一行列头，删掉 3 处重复图例

组头上方放一行 12px 灰列头：能力 / 风险 / 本租户覆盖 /（最后一格留给「详情」）。空档从「不知道对齐什么」变成「列与列之间」；三处「当前生效 → 本租户覆盖」删掉，图例只出现一次。

好在：零新增交互，行高不变，手机上隐藏列头即可；顺手把重复文案清了。
代价：多一行 28px；列头文案要短，否则手机档要处理折行。
乙 乙 · 风险徽章紧跟名字

徽章从右边挪到名字右侧（名字 + 徽章成为一组），右侧只留「下拉 + 详情」。

好在：不动网格列数，改动只在模板顺序。
代价：徽章长度不一（高危/中危），紧跟名字会让每行的第二列起点参差；空档仍在，只是挪了位置。
丙 丙 · 条件升成独立列，做成真表格

把名字下面那行小字（出现条件）提成单独一列：能力 | 出现条件 | 风险 | 本租户覆盖 | 详情。空档被真内容填满。

好在：最像表、最整齐，横向信息量最大。
代价：手机档要再折一次（三排）；条件文案长度差异大，列宽不好定；改动最大。
方案第一次来日常用防呆适合谁代价
甲 ★列头一句话说清每列是什么不看列头也熟了，零操作变化图例只出现一次，不会重复干扰所有人多 28px 高度
乙名字和徽章连在一起，读得快零操作变化徽章宽度差异会造成列起点参差只看高危的人视觉不齐
丙信息密度最高横向扫一眼就能比条件手机档三排，容易看串行常批量比条件的人改动最大、手机最挤

Q4 · 顶部四条横带

进门先过四道不同高度的横带

现在从上到下是：① 标题行（含右侧「只看高危」）② 两行说明 ③ 42px 琥珀色体检条 ④ 分段控件 + 一句提示。四条之后才是第一行能力。

★ 推荐 甲 · 说明收进「?」，视图控件并成一行

两行说明收进标题旁的「?」悬浮提示（第一次来点一下就有）；「只看高危」从标题行挪下来，与「按行微调 / 一键推荐」并成同一行工具条；体检条紧跟标题。

好在：首屏少两条横带（约 60px），且同一行的两个控件都是「看哪些、怎么看」，语义一致。
代价：说明变成「要点一下才看到」，得保证「?」够显眼；老用户可能一时找不到那段话。
乙 乙 · 只压缩，不搬家

说明改一行、体检条改更紧凑、分段控件行的提示删掉。结构仍是四条，只是每条更矮。

好在：零学习成本，改动最小。
代价：四条还是四条，节奏依旧碎；省下的只有约 30px。
丙 丙 · 说明整段删掉

直接删掉那两行说明，其余不动。省 44px，最快。

好在：一秒钟改完。
代价：第一次来的人不知道下拉改的是「本租户覆盖」、不知道「保存后对下一轮新会话生效」——这两句是防误操作的关键。
方案第一次来日常用防呆适合谁代价
甲 ★点「?」才知道两句关键提示首屏直接是清单，少滚 60px「?」需要足够显眼，否则等于丢了提示多数人已熟悉本页提示藏起来一点
乙提示都在，节奏仍碎略紧凑不变要保守收口省得少
丙少了关键提示最快容易误操作（不知道改的是覆盖档）不推荐防呆能力下降

Q5 · 外部服务那格三行命令

小修，但它把表格撑歪了
