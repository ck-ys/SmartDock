启动链

index.html 只做一件事：挂载 src/main.ts。真正的初始化在 main 里按固定顺序执行。

顺序做什么失败表现
1创建应用、装 Pinia白屏 + 控制台报错
2装路由与守卫页面能开但无权限判断
3装 Element Plus 与全局样式组件无样式

5mount 到 #app白屏

目录职责

目录放什么不要放什么

src/views/页面，按域分目录跨页复用的重型组件
src/components/跨页复用组件只给一个页面用的私货

CHAPTER 03

路由与权限

前端的权限只有三件事：能不能进这个页面、看得见哪些菜单、点不点得到这个按钮。三件事的数据源都在后端。

全局守卫

每次跳转都会先过守卫：有没有 token → 有没有用户信息 → 有没有拉过路由。三者缺一个就先去补齐，再放行。

白名单与死循环

登录页、错误页必须在白名单里，否则未登录时会被反复重定向。守卫里调用接口失败要落到错误页，不能无限重试。

动态菜单

侧栏不是写死的：后端按角色返回菜单树，前端转成路由再 addRoute。所以“页面存在但菜单没有”就是看不见。

环节数据出错表现
菜单表sys_menu 的 path / component / perms页面 404 或侧栏缺项
接口getRouters整棵菜单为空
转换组件路径 → 动态 import点菜单白屏
注册router.addRoute刷新后 404

按钮权限

v-hasPermi 在挂载时直接移除 DOM，不是隐藏。所以“看不见”和“点得到”是同一个判断。

模板里
<el-button v-hasPermi="['dcs:task:publish']" type="primary" @click="publish">发布</el-button>
两段式权限串无效

dcs:task 这种两段式匹配不上超管的 *:*:*，结果是超管也看不到按钮。必须三段式。

路由写法

固定页（无需菜单）
{
  path: '/ai/assistant-admin',
  component: () => import('@/views/dcs/assistant/admin/index.vue'),
  meta: { title: '助手管理' }
}
  • 业务页优先走菜单动态注册，不手写路由。
  • 固定页用于跳转目标、详情页等不需要出现在侧栏的页面。
  • meta.title 会进标签页与面包屑，写人话。
CHAPTER 04

请求层

所有请求只有一条路：src/utils/request.ts。它统一带 token、统一弹错误、统一处理 401。

一次普通请求

阶段发生什么
发起页面调用 api/<域>/<资源>.ts 里的函数
拦截加 token、租户头、clientid
代理/dev-api 转发到 8090
返回拦截器判 code：非 200 弹提示并 reject
解包页面用 r<T> / table<T> 取数据

封装与返回

api 文件写法
import request from '@/utils/request';
import type { AxiosPromise } from 'axios';

export function listTask(query: TaskQuery): AxiosPromise<TableDataInfo<TaskVO>> {
  return request({
    url: '/dcs/task/list',
    method: 'get',
    params: query
  });
}
返回的是整个 body

request.ts 没有做 data 解包。页面里用 const res = await listTask(q); rows.value = res.rows;；再套一层 .data 会拿到 undefined。

下载与上传

下载

用封装好的 download 工具，带 token 走 blob；不要用 window.open 裸链，会丢鉴权头。

上传

走 el-upload + 项目封装的 action 地址；上传成功后后端返回文件 id，不要自己拼 URL。

SSE 两种通道

通道用途实现
通知站内消息、公告推送utils/sse.ts，EventSource
智能体对话流式事件utils/aguiClient.ts，fetch + ReadableStream
不是同一个东西

智能体通道要 POST、要带 body、要自己解析分帧，所以不能用 EventSource。排障时先确认走的是哪个通道，别拿通知的日志去解释对话。

CHAPTER 05

页面开发流程

一个页面从需求到可验收，只有五步：菜单 → 页面 → 接口 → 权限 → 双视角。顺序不要倒。

新增页面

  1. 建菜单sys_menu（baseline + migration 双写），确定 path、component、perms。
  2. 建页面src/views/<域>/<页面>/index.vue，先静态，再接数据。
  3. 建接口src/api/<域>/<资源>.ts + TS 类型。
  4. 接权限新增/编辑/删除按钮挂 v-hasPermi。
  5. 双视角验收超管看全量，普通用户看裁剪；清缓存冷启动再走一遍。

新增 API

命名对齐

前端函数名与后端方法语义对齐：listXxx / getXxx / addXxx / updateXxx / delXxx。类型名用 XxxVO / XxxForm / XxxQuery，与后端四件套对应。

按钮权限

处写什么
后端@SaCheckPermission("dcs:task:publish")
菜单表sys_menu.perms = 'dcs:task:publish'（按钮类型菜单）
前端v-hasPermi="['dcs:task:publish']"

列表页标准结构

区块约定
查询区表单 + 搜索/重置；queryParams 与分页同对象
操作区新增/批量/导出，全部挂权限指令
表格v-loading + 空态 + 分页；列宽固定，避免跳动
弹窗新增/编辑共用一个表单组件，open(mode, row?)

CHAPTER 06

状态与存储

页面状态留在页面，跨页状态进 Pinia，需要跨刷新的才进 localStorage。三层不要混。

Pinia 分工

模块存什么谁在用
usertoken、用户信息、角色与权限守卫、指令、请求头
permission动态路由表、侧栏菜单路由守卫、壳层
app侧栏开合、设备类型、尺寸布局
tagsView标签页与缓存页壳层
dict字典缓存各业务页
settings主题、布局偏好全局

localStorage

键内容注意
token登录令牌过期时间由后端控制，前端不自行续期
用户偏好侧栏、主题换账号应保留（属于浏览器）
业务草稿未提交表单要能清理，不能永久脏数据

切账号要清什么

  1. 清 token 与用户信息只清 token 不清用户信息，会出现“旧身份 + 新 token”。
  2. 清动态路由否则新账号会看到上一个账号的菜单。
  3. 刷新页面确保 Pinia 与内存态全部重建，而不是只改字段。
验收专用

双视角验收时，切账号必须先清 localStorage 再登录；直接换账号登录会残留菜单，测出来的权限是假的。

CHAPTER 07

样式与令牌

样式不是“看着差不多”。字号、圆角、间距都有令牌，改完要过门禁、做计算样式断言、再看截图。

设计令牌

类别档位写法
字号12 / 13 / 14 / 15 / 20 / 26var(--dcs-font-*)
圆角2 / 4 / 8 / 12，胶囊 999pxvar(--dcs-radius-*)
颜色纸底、墨色、主色、线色var(--dcs-*)
间距4 的倍数页面内自定义 SCSS 变量
定义与门禁
frontend/src/assets/styles/dcs-tokens.scss      // 令牌定义
frontend/src/assets/styles/tokens.test.ts       // 档外字面量 px 即失败
frontend/src/assets/styles/tokens-baseline.json // 存量豁免，只减不增

样式验收

改 CSS / 图表 / 颜色 / 布局，必须走完这条链；少一步都不算验过。

  1. 计算样式断言getComputedStyle 取实际值；attribute 值不等于渲染值。
  2. 截图1440 与 390 两档，至少两个数据规模。
  3. 原生读图当前模型支持图片就直接 Read 打开 PNG 目检，不绕视觉 MCP。
  4. 修复类补前后对比修复前真机截图 + 修复后截图，出对比页。
SVG 样式铁律

SVG 上的样式一律用 :style CSS 对象。写在 attribute 上的值不参与渲染计算，断言会永远对不上。

令牌门禁

门禁扫描 src/**/*.vue 的 <style> 与 *.scss，命中档外字面量 px 就失败并报 文件:行；var(--dcs-*) 放行。

情况怎么办
新代码写了 font-size: 13.5px改回令牌档位；没有合适档位就先讨论，不要加豁免
存量文件报错修掉一处就删 tokens-baseline.json 一行
想加豁免禁止 baseline 只减不增
CHAPTER 08

智能体前端

助手是前端里唯一一条“长连接 + 状态机 + 多宿主”的链路。看懂三件事就够：单例、发送、事件。

三个宿主一个单例

工作台、业务壳、会话页三处都能打开助手，但共享同一个 getAssistant(userId) 实例；否则同一用户会挂多条连接、状态互相覆盖。

改共享件的代价

DcsAssistant 下的组件与 layout/index.vue 是共享件：改一处，三个宿主都要回归。拍板/计划里必须标“影响面：共享件”。

一次发送

从点发送到看到第一个字，中间经过参数组装、POST、分帧解析、状态更新四段。任何一段断了，表现都是“没反应”。

段关键动作失败表现
组装forwardedProps 带模型、思考档位、技能开关模型不生效 / 档位被忽略
发送aguiClient POST /agui/run/{agentId}没请求，控制台无记录
解析按行分帧，交给 onCustom 与标准事件分支有请求但界面不动
更新写入消息流、工具卡、计划卡有帧但没渲染
思考档位是产品行为

“快速 / 平衡 / 深入”是一个字段，影响模型推理预算。mock 与实现都必须保留 brain 图标、文字、chevron 三件套，不能简化成灰字。

事件与渲染

事件渲染成什么
RunStarted / RunFinished工作态开始/结束、计时停止
TextMessageContent消息正文逐字追加
ToolCallStart/End工具卡片：名称、参数、结果
StateSnapshot/Delta会话状态栏、上下文占用
自定义帧（11 种）计划卡、待办、技能、计费、压缩、心跳等
核心函数做什么改错时的表现
runTurn组装 forwardedProps、发起请求、消费事件流没请求，或有请求没帧
onCustom把 11 种自定义帧分发到对应卡片状态有帧但界面不渲染
resolveHitl收集待确认项，整批回传后重跑确认了但一直卡住
getAssistant按用户复用单例，三个宿主共享多宿主状态互相覆盖
attach按 thread 重连事件流并补拉历史刷新后内容丢失
startTurn创建本地回合与占位消息消息重复或顺序错乱

HITL

人工确认是“暂停 + 重跑”，不是“点一下继续”。前端要做的是：拿到待确认列表 → 渲染卡片 → 收集决定 → 带着全部 id 再发一次 run。

只回传一个 id 会卡死

一次 run 可能产生多个 interrupt。少传一个，后端仍在等待，前端看起来“确认了但没动”。必须整批回传。

恢复与重试

场景正确做法错误做法
流断了用同 thread 重新 attach，再拉一次历史直接重发消息，产生重复回合
卡在确认重新查 pending，整批回传刷新页面当作已确认
运行超时看门狗标记失败并提供重试入口无限等待，界面一直转
重复 run复用原回合 + 新 runId同 runId 重试，撞 409

加自定义帧

  1. 后端发帧定义 name 与 payload，写进事件协议表。
  2. 前端分支onCustom 里加 case，写入对应状态。
  3. 渲染组件新卡片组件或复用现有卡；空数据要有兜底。
  4. 回归旧会话回放不报错；未知帧被忽略而不是崩。

助手排障

现象先查
没发出去agentId / threadId 是否为空；按钮是否被禁用
有请求没帧Network 里响应是否流式；分帧解析是否报错
有帧没渲染onCustom 是否有该 name；组件是否注册
刷新丢内容是否先拉历史再 attach；store 是否被重建
卡在确认pending 列表与回传 id 数量是否一致
CHAPTER 09

布局与壳层

壳层只做四件事：放导航、放内容、放标签页、挂全局组件。业务逻辑不许写进 layout。

壳层结构

区域组件职责
顶栏Navbar面包屑、搜索、全屏、用户菜单
侧栏Sidebar动态菜单、折叠、当前项高亮

内容区AppMain路由出口 + keep-alive
全局挂载layout/index.vue挂助手等跨页组件（L37）

改壳层的三条纪律

  1. 先确认影响面壳层是所有业务页的父容器，改间距/宽度会影响全部页面。
  2. 1440 与 390 都看侧栏在手机上变抽屉；折叠后不许出现横向滚动。
  3. 别把业务塞进来需要跨页常驻的组件用挂载点，不要写业务判断。
多窗口并行

壳层文件（index.html、layout、changelog、助手组件、vite 配置）是高频冲突区。别的窗口正在改时不要碰，先沟通。

CHAPTER 12

排障手册

白屏先看控制台，401/403 先看 token 与权限串，没数据先看 Network，助手问题先分“发没发出去”。

决策树

先拿三样东西

① 浏览器控制台第一条报错；② Network 里失败请求的状态码与响应体；③ 当前账号权限。三样齐了再判断。

白屏与 401/403

现象先查根因
白屏 + 控制台报错构建错误、未捕获异常、路由 component 路径动态 import 路径写错
白屏无报错根节点是否挂载、CSS 是否把内容藏了容器高度 0 / display:none
401token 是否存在、请求头是否带 clientid切账号没清 localStorage；头重复发
403权限串、菜单 perms、角色两段式串；菜单没同步
菜单缺项getRouters 返回、组件路径菜单没配或 component 写错

没数据与样式不生效

  • 接口 200 但列表空：看响应 rows/total；确认查询参数与分页；确认不是后端租户过滤。
  • 接口 200 但页面报错：看是不是多取了一层 .data。
  • 样式不生效：看是否有 scoped 穿透问题；看是否被更高优先级覆盖；SVG 看是否写成了 attribute。
  • 改了没反应：确认 Vite 热更新已生效；端口是否连到旧实例。

助手断流

现象先查
点了发送没反应Network 有无 /agui/run；按钮是否 pending
请求挂起无响应响应头是否 text/event-stream；代理是否缓冲
半个字后停住分帧解析是否抛错；连接是否被网关超时切断
刷新后历史丢失是否先拉历史再 attach；threadId 是否持久化
Playwright 注意事项

助手页有长连接，networkidle 会一直等不到。用 domcontentloaded + 显式等待元素，不要用 networkidle 判加载完成。
